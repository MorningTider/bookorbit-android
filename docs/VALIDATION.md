# Android 阅读器验收记录

## 2026-11-13 自定义字体跨章节卡顿修复

当前自用包为 `0.8.0-custom.3`，版本码803，功能对应BA-C38。用户复现条件为设置文字字体后翻到下一章节。原版本为custom.2及提交99937ac。

### 修改前复现

在API35原生WebView使用26,273,008字节的系统NotoSerifCJK测试字体与合成六章TXT。五次直接章节跳转分别耗时[2814, 2508, 2740, 1562, 2401]ms，前台章节与后台页码测量合计读取同一字体11次。新回归断言每组字体只读取一次，在旧版实际失败。

旧实现向每个独立章节和隐藏测量文档注入URL形式的CSS字体，每个文档重新加载。字体处理仍在章节显示前同步等待，大型中文字库把等待放大到秒级。

### 修复与同条件复测

同一字体组的FontFace加载Promise和解码结果由前台章节与后台页数测量共享，再注册进各文档的FontFaceSet。继续等待正文、粗体标题、斜体和书内字体就绪。字体选择发生变化时丢弃旧加载结果，释放本阅读器注入的旧字体，保留书内字体。字体请求失败可重试。

- 独立复测同一TXT的五次直接跳章为[21, 20, 21, 21, 30]ms，字体读取1次。最终完整回归中该项为[131, 159, 455, 215, 156]ms，读取仍为1次。耗时随模拟器负载变化，记录两轮原始值。
- 先打开书、选择字体，再从章末仿真翻入下一章的EPUB为[386, 531, 511, 379, 383]ms，TXT为[629, 575, 505, 369, 431]ms。这些值包含卷页动画及原生显示确认。两者字体均读取1次，正文与大小标题均检查字体就绪。
- 新回归还暴露TXT章节URL在前台与后台分页同时使用时被提前回收，导致加载文档为空。已增加独立引用计数，最后一个使用者释放时才撤销URL，JS和原生TXT仿真跨章均通过。

### 完整回归

Full与F-Droid各341项JVM测试通过，零失败、零错误、零跳过。JS45项、中英文620项资源与参数检查通过。Full常规22项、320dp窄屏及1.5倍字号12项、F-Droid品牌和数据库迁移4项通过。APK、原生测试包及双变体Lint均通过，Lint保留零错误、145项既有警告和1项提示。模拟器恢复Full及原有显示设置。

### 卷页绘制记录

首次完整复验发现点击卷页在WebView排版阻塞时，基于墙钟的动画可能跳过中间纸张帧。改用 `postOnAnimation` 调度，单次推进上限32ms，保留系统关闭动画、取消恢复、导航就绪和超时回收。测试通过实际OnDraw观察中间纸张帧，并继续检查按住800ms、松手提交、拖回取消和连续正反翻页。

最终API35模拟器采集64帧，输入至首个纸张绘制约18.91ms，总帧耗时中位数101.39ms，P95为151.14ms，最大184.75ms。绘制耗时中位数0.78ms，记录的帧间隔中位数33.33ms。64帧超过16.7ms，模拟器仍有慢帧，真机流畅度保留为待验项。
